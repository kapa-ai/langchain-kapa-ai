Fernwick Relay user guide

Fernwick Relay is a fictional webhook relay. It receives webhooks from upstream services, stores each one, and delivers it to the endpoints you register. This guide covers installation, relay configuration, retries, signing, and limits.

Install the relay agent

The relay agent runs on Linux and macOS. Install it with pipx install fernwick-agent, then run fernwick login with a workspace token. The agent requires Python 3.11 or later and stores its configuration in ~/.config/fernwick/agent.toml.

Configure relays

A relay connects one inbound address to one or more destinations. Create a relay with fernwick relay create --name billing --destination https://billing.internal/hooks. Each relay can have at most 8 destinations. Destinations receive every webhook in the order Fernwick received it, unless you enable parallel delivery with --parallel.

Retry policy

When a destination does not answer with a 2xx status within 10 seconds, Fernwick retries the delivery. Retries use exponential backoff that starts at 2 seconds and doubles on every attempt, capped at 5 minutes between attempts. After 12 failed attempts the delivery moves to the dead letter queue, where it stays for 7 days.

Signing secrets

Every delivery carries an X-Fernwick-Signature header with an HMAC-SHA256 signature of the raw request body. Each relay has its own signing secret. Rotate it with fernwick relay rotate-secret; the previous secret remains valid for 24 hours so destinations can switch without dropping deliveries.

Limits

A single webhook payload can be at most 256 KiB. Larger payloads are rejected with HTTP 413 at the inbound address. The free plan relays up to 10,000 webhooks per month; the team plan relays up to 2 million.

Troubleshooting

If deliveries stop, run fernwick doctor. It checks the agent version, the workspace token, and the reachability of every destination, and prints the first failing check. A destination that answers with HTTP 410 is disabled automatically and must be re-enabled by hand.
